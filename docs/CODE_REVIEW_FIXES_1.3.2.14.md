# Confirmed code-review repairs for 1.3.2.14 Beta

These changes repair the eleven confirmed defects in the read-only review of `abbe3c184a4d9f0d03778be5ddb82a7cb43f0eae`. The propagation autofill patch is retained. This work changes failure handling and state synchronization, without changing manual-review layouts or controls. It does not apply the speculative speed proposals from that review.

All tests use disposable profiles. Intentional unresolved catalog/socket contradictions, manual propagation approval, screenshot previews, frozen capture identities, remnant logging, saved recipe/family IDs and Analysis Context remain in place. The supplied catalog data and OCR recognition models/thresholds are unchanged. Unsupported numeric tokens remain editable in the existing manual review.

A capture adapter blocked inside external code cannot be safely killed as a Python thread; one physical owner remains bounded until that adapter returns. The user receives a retryable busy error rather than a stuck Reading state or unbounded abandoned threads. Screenshot cleanup preserves an image when storage cannot safely confirm that it is unreferenced. These guards protect shared captures and do not hide the original operation error.

Publication requires the complete Windows regression suite, native Windows HUD input, the 100-map logging/export workflow, and frozen-runtime/installer/update checks on the combined source. Local focused results do not replace those platform gates. The native HUD uses a simulated game view, and the 100-map workflow injects recognition results; live OCR accuracy is documented separately in the original-capture propagation report.
